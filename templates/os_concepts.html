SafeFS: Bridging Operating Systems Theory & Practical Systems Engineering

SafeFS is designed as a foundational Operating Systems course capstone project. It demonstrates core OS design principles: Virtual File Systems (VFS), Inode data structures, event-driven asynchronous I/O notifications, journaling & transactional rollbacks, thread concurrency & locking, cryptographic integrity, and process control telemetry.

1. Virtual File System & Inode Abstraction
VFS / FCB

In traditional UNIX operating systems, every file is represented by an Index Node (inode), and in Windows by a File Control Block (FCB) inside the Master File Table (MFT).

SafeFS Implementation:
SafeFS maintains an internal SQLite relational schema (`files` table) simulating the operating system's Inode Table. It isolates file identity (`file_id`, `path`, `filename`, `relative_path`) from content blocks (`size_bytes`, `sha256`, `last_modified`), mirroring how modern kernels decouple file names in directories from disk metadata.
2. Event-Driven I/O & Kernel Notifications
Interrupts / inotify

Polling the file system continuously consumes high CPU and causes disk thrashing. Modern kernels provide asynchronous directory change notification subsystems that deliver event interrupts to user-space applications.

SafeFS Implementation:
Using Python Watchdog, SafeFS hooks directly into:
  • Linux: inotify(7) subsystem (non-blocking kernel event queues).
  • Windows: ReadDirectoryChangesW with I/O Completion Ports (IOCP).
3. Journaling, Rollback & Copy-on-Write
Atomic Storage

Advanced file systems (ZFS, Btrfs, WAFL) utilize Copy-on-Write (CoW) and transactional journaling to prevent data corruption during power loss or system failure.

SafeFS Implementation:
SafeFS enforces a strict zero-data-loss invariant. When a file is modified, an immutable point-in-time snapshot is stored in isolated storage before mutations proceed. Crucially, before any version restore occurs, a PRE_RESTORE snapshot of the target is guaranteed.
4. Cryptographic Hashing & Silent Data Corruption
SHA-256

Standard OS timestamps (st_mtime) can easily be spoofed by malware (timestomping) or become inaccurate. Detecting unauthorized modification and silent data corruption (bit-rot) requires cryptographic block verification.

SafeFS Implementation:
SafeFS utilizes streaming SHA-256 block hashing (64 KB buffers) to verify integrity without loading entire files into memory. It compares on-disk hashes against trusted database baselines to identify unauthorized drift.
5. Concurrency, Threading & Synchronization
Mutex / WAL

Handling concurrent file writes, multi-threaded watchdog event queues, and database updates introduces critical section race conditions.

SafeFS Implementation:
SafeFS protects state using Python threading.RLock() mutex primitives, event debouncing to avoid write-burst races, and SQLite's Write-Ahead Logging (WAL) mode to achieve concurrent multi-reader, single-writer ACID guarantees.
6. Process Accounting & Hardware Telemetry
PCB / psutil

Operating systems maintain a Process Control Block (PCB) for every active task, tracking PID, memory allocations (RSS, VMS), CPU times, open file descriptors, and thread counts.

SafeFS Implementation:
Via psutil, SafeFS exposes its own internal PCB metrics alongside host telemetry (per-core CPU scheduling, virtual memory paging, storage partition statistics, and disk I/O throughput).
